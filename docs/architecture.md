# 架构与安全边界

## 数据流

`library/`（仓库内资料库） → 只读元数据扫描 → `data/local/index.sqlite3` → 本地 API → 浏览器界面。

- 索引器只调用目录枚举与文件 `stat`，不打开文件内容。
- 源根目录默认为仓库内 `library/`；可用 `--source` 指向其他只读目录。历史上曾索引 `E:\Games\GameTools`，现已移出默认流程。
- 白名单内的可执行文件、动态库与压缩包只保存元数据。
- 预览接口必须由用户针对单个索引记录触发；文本上限 2 MB，图片上限 30 MB。
- `.exe`、`.dll`、安装包、脚本、压缩包、Office/PDF 等不通过内容接口提供，仅展示元数据。
- 源路径会经过索引存在性检查、规范化和根目录边界检查。

## 本地运行

```powershell
py -m gamewiki.indexer
py -m gamewiki.server
```

打开 `http://127.0.0.1:8765`。索引数据库是本地生成物，不提交到 Git。

## 已知缺口

- **PDF 与 Office 文档无法预览**：`TEXT_PREVIEW_EXTENSIONS` 不含它们，接口一律返回「仅元数据」。资料库中此类文件占比不小，属于当前最主要的功能缺口。
- **索引无增量刷新**：`scan()` 每次全量重建，索引是一次性快照；源目录变动后需手动重跑，否则记录会指向已不存在的路径。
- **悬空记录的错误提示不准确**：源文件缺失与索引库缺失都抛 `FileNotFoundError`，接口统一回「索引尚未建立，请先运行扫描。」，与真实原因不符。

## 既有成果

`legacy/jcwiki` 保存从 `jcwiki-main.zip` 导入的既有 GitHub 静态页面、资料与生成脚本。它们仅作历史成果管理，未接入主索引流程，也不会被主应用执行。
