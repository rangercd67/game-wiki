## 第二轮：《集批宝典》全表导入（同日）

### 抓取（保存到本地）

**通道**：`tenant-docs-plugin` MCP 不可用（`connector_disabled`），改走匿名 web 路线：
从 `https://docs.qq.com/sheet/<id>?tab=<tab>` 页面里 regex 出
`src="//docs.qq.com/dop-api/opendoc?..."`，该 URL 自带完整参数集
（`u=` `startrow/endrow` `block_start/end_row/col` `callback=clientVarsCallback` `t=`），
直接 GET 即 200。响应是 JSONP，`clientVars.collab_client_vars.initialAttributedText.text[0]`。

**解码**：据 `block_datas[n].related_sheet` = base64 → zlib → **protobuf**，无 `.proto`，
于是写了个通用 wire-format 解析器反推 schema：

```
root.f5[?].f19 = { f3:元信息  f4:样式表  f5:共享字符串池   f6:4096 项(列定义 + 单元格) }
池条目 = 0a <len> <utf8>        # 文本内可含换行，必须按长度读，不能靠叶子拼接
单元格 f3 = { f1:kind(1空/2数值/4文本)  f2:{f1:池下标}  f4:{f1:样式下标} }
同 block 里另外 219 个切片是合并单元格范围
```

踩坑：`first_varint()` 一开始对「自身就是 varint」的节点去遍历 children 返回 None，
导致行/列全丢、每张表都返回 0 个单元格；`with_range()` 忘了覆盖 `tab` 参数，
导致 23 张表抓回同一张。都已修。

**结果**：23 个子表，21 张取到数据（最大 仙术杯#6 选手统计 573×28 / 5633 非空格），
2 张（通宝交换学一图流、终曲合声路线图）内容全是贴在表上的图片，`grid` 为空——
不是抓取失败，是原表里就没有数据。产物落 `library/明日方舟-集批宝典/原始导出/`
（21 组 CSV+JSON + `_index.json` + 4 个脚本），另有 `索引.md`。
