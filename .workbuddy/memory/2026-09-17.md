## 关键设计决定

1. **渲染器先整篇转义再解析**，且不能用 `html.escape`——它会把 `>` 转成 `&gt;`，
   直接毁掉引用块语法。转义只在 `render()` 入口做一次，`inline()` 契约是「入参已转义」。
   踩过的坑：`_attr()` 二次调用 `_text()` 会产出 `&amp;amp;`，被用 `inline()` 直测的用例掩盖了。
2. **大表格不进 Markdown**：结构化数据放 `content/data/<game>/<name>.json`，
   由 front-matter `data:` 引用，生成器渲染成带筛选的 HTML 表。1600 行的面具总表走这条路。
3. **图片不进内容源**：`content/media.json` 存「输出名 → library 相对路径」映射，
   构建时才从 `library/` 取并按需缩放。否则 115MB 原图会进 git。
4. **输出全用相对路径**：内容里写 `/media/x.png`，生成器按页面深度改写成 `../../media/x.png`。
   同一份产物既能挂 `example.com/` 也能挂 `example.com/repo/`。
5. **声明式素材清单**：真实工作簿有 30 个工作表，自动一个表建一页会产出大量重复页面。
   清单是编辑决策，代码只负责执行。

## 素材现实（踩坑记录）

- **编码不统一**：`印象空间之宝魔出现位置.txt` 是 GBK，用 UTF-8 读会整篇乱码但不报错。
  已加 UTF-8 → GB18030 → Big5 回退链。
- **留空表示「同上」**：合成表的 `Lv`/`名称` 列大量留空，靠视觉分组。
  需要 `fill_down` 按列向下填充，且必须**按列声明**——掉落列的空白是「无掉落」而非「同上」。
- **署名散落**：`本攻略由B站up主：猎猫人老贾独立制作` 等，会混进数据行。
  已做「署名行摘出 → 页面底部出处块」，公开站点必须保留出处。
- **目录名与我的猜测不符**：`全装备列表及获得方式`（不是「获取」）。找不到就报错跳过，不猜。
