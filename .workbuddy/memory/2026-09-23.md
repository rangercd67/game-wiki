### 两版方案的取舍（重要，别再走弯路）

1. **不用 `git subtree push`**：`dist-wiki/` 是构建产物且被忽略，subtree 要求它在 `main`
   上被跟踪，会导致每次重建都往 `main` 历史里再塞一份 70 MB。
2. **不用「造无父提交再强制推送」**（第一版实现）：实测**每次发布都重传全部 70 MB**。
   原因是无父提交时客户端手里没有远端旧提交的对象，打包时无法把它们排除——
   `size-pack` 从 68913 KB 涨到 137826 KB，正好翻倍。
   改成持久克隆后：重复发布「没有新提交」，单文件改动只推一个提交，`size-pack` 不再增长。
3. **远端是本地路径时必须转绝对路径**：缓存仓库的 cwd 和主仓库不同，相对路径在
   第二次发布会解析到缓存目录里去（`tmp/deploy-cache/tmp/xxx.git`）。
   这个 bug 只有拿本地裸仓库当远端测才会暴露，URL 形式的远端一辈子碰不到。

## 图片体积：已解决（PNG → WebP）

原来的判断有一半是错的，值得记下来。`dist-wiki/` 70.49 MB 时我以为是「Pillow 没装、
`max_edge` 没生效」。实测：Pillow 12.3.0 **是装好的**，`max_edge`（1920/2200）
**也真的执行了**——但这些图**原始就只有 ~1130px 宽**（PNG 最大 1137x638），
阈值根本没触发过，所以缩放从来不是问题。

真正的问题只有一个：**PNG 是 3D 截图的糟糕容器**。
1124x635 的殿堂走法截图存成 PNG 要 1.25 MB，合 **1.75 字节/像素**，几乎不压缩。

做法：`--image-format {webp,keep}`，默认 webp，**只转 PNG**（JPEG 本就够小，
二次有损不划算）。内容源里仍统一写 `.png`（作者视角稳定），投递格式由构建决定，
`build_media` 返回「内容源名 → 实际文件名」映射，页面渲染时按 `_MEDIA_REF` 改写引用。
Pillow 缺失自动降级为原始格式。

结果：**PNG 60.17 MB → WebP 8.06 MB（7.5x），整站 70.49 → 18.39 MB（3.8x）**，
240 个文件数量不变。已逐张目视确认，含小字号表格文字（p3p 合成表的路西弗/阿特斯
那一屏）依旧清晰，`WEBP_QUALITY = 90`。

## 顺手抓到的真 bug：侧边导航游戏标题链接

`_render_nav` 里游戏标题用的是 **`index_page.prefix`**（链接目标自己的深度），
而不是当前页的深度。游戏首页恰好是深度 1，于是那 4 个页面上碰巧成立，
**其余 53 个内容页的侧边导航整片 404**，共 212 条死链。

这类 bug 构建不报错、页面能开、48 个单测全绿、体积统计也正常，
**只有把每个 href 落到磁盘上才能发现**。

## 部署阻塞点

`git` 本机**没有任何写凭据**：无 `~/.git-credentials`、无 `~/.ssh`，
凭据助手是 GCM 2.9.0（系统级 `manager` + 用户级 exe 路径，两个都指 GCM），
但没存过任何凭据。远端已配好：`origin = https://github.com/rangercd67/game-wiki.git`。

**`mcp.json` 里那个 PAT 是死的**。`C:\Users\Administrator\.workbuddy\mcp.json` 的
`github-token` server 有明文 `GITHUB_TOKEN`（`ghp_` 开头、40 字符、无空白），
但 `Authorization: token` 与 `Bearer` 两种方案都返回 **401**，而匿名调
`api.github.com/users/rangercd67` 返回 200——所以不是网络/代理问题，是令牌本身
过期或被撤销（GitHub 会撤销它发现在明文文件里的经典 PAT）。

**连接器用的是另一套凭据**（应用自己的 OAuth），所以 GitHub MCP 工具能用，
但这个 PAT 不能用于 `git push`。而且该 OAuth **没有建仓权限**：
`create_repository` 返回 `403 Resource not accessible by integration`。

结论：仓库必须由用户自己建，推送必须由用户自己授权（GCM 浏览器登录）。
