### 本次踩到的沙箱坑（已写进用户级记忆，另立技能）
1. **`shutil.rmtree` / `rm` 有「批量删除守卫」**：单次请求累计删除 ≥ 50 个文件即
   返回 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 并中止。
   **后台运行不会触发宿主确认弹窗**（我第一遍就这么白跑一次）；
   **前台重跑**时宿主会弹确认框，批准后才放行并提示 `Sandbox bypassed (escalation-approved)`。
   守卫状态在 `%TEMP%\codebuddy-safe-delete-bulk\<sha256(sessionId)>\state.json`，
   批准是**按 tool-call id** 记的（`toolApprovals`），重放同一条命令才生效。
   **不要自己去改 state.json 或调 guard 的 `approve` —— 那是绕过安全控制。**
2. **`.ps1` 里只要含 `Remove-Item`，脚本一执行整个 PowerShell 会话就被杀**（exit 1，
   连 `trap` 都来不及写、stdout/stderr 全无）。同样的操作**内联成命令就正常**。
   → 需要 PowerShell 删除注册表时，**写成内联命令，别落盘成脚本**。
3. **PowerShell 5.1 不支持 `(if ... else ...)` 当表达式**（`$x = (if (…) {…} else {…})`
   直接 ParserError）。要用语句式先赋值，或 `$(if …)`。
4. **注册表字面 `*` 键**（`HKLM\SOFTWARE\Classes\*`）：`-LiteralPath` 也解析不了，
   得 `Get-ChildItem -LiteralPath 父键 | Where-Object { $_.PSChildName -eq '*' }`。
   顺带：**不带 `-LiteralPath` 的 `Test-Path`/`Get-Item` 遇到路径里的 `*` 会通配展开**，
   会产出「看起来有 278 个值、实际只有 139 个」这种虚高计数（本次就着了）。
5. PowerShell 工具的 stdout 一律被吞 → **所有结果写文件再读**。
   含中文的 `.ps1` 会因 GBK 解码变乱码（本次一句中文注释被读成 `鏄惁瀛樺湪`），
   **脚本保持纯 ASCII**。
